## FAIL verdicts

### J17 — Cloudshredder Sliver / `SubtypeCreaturesHaveKeywordListRule`
**Verdict:** FAIL
**Issue:** New rule mis-captures a sibling ("Equipped creatures you control have flying and haste." — Dalakos, Crafter of Wonders) as a creature subtype.
**Rule citation:** CR 301.5 (Equipment / "equipped" is a state, not a subtype); the rule's own cites CR 604.2 / 702.9 / 702.10 are all valid.
**Rule text:** > CR 301.5c: "A permanent is attached … A permanent that's a creature to which an Equipment is attached is 'equipped.'" — "equipped" describes a state, and there is no creature subtype "Equipped."
**What the rule does:** subject capture `(?<sub>[A-Z][a-z]+)\s+creatures?\s+you\s+control\s+have …`, declining only `{Other, Nontoken, Attacking}`. On Dalakos it emits `Subtypes=["Equipped"]` + GainAbility(flying) + GainAbility(haste).
**Why this misrepresents the rules:** "Equipped" is not a creature subtype; the correct filter is a state/equipped characteristic over creatures you control. Because this is a **two-keyword** grant, `BareKeywordGrantRule` (priority 967) declines it (its single `kw` group makes `MapKeywordToStaticAbility("flying and haste")` return null) and no other rule owns it — so Dalakos was previously unparsed and the new rule (priority 975, dispatched first) **newly introduces** a wrong parse. This is precisely the mis-capture the offline edge-diff gate would flag.
**Suggested fix:** validate `sub` against a real creature-subtype list (or at minimum add `Equipped` — and ideally `Land`, `Modified`, `Tapped`, colors, `Multicolored` — to `_reservedNonSubtypeWords`) so the rule declines Dalakos and a state-characteristic filter can model it.

**Note on the fixture:** the Cloudshredder Sliver gold itself is faithful — "Sliver" IS a creature subtype, flying is modeled as `evasion` (`CanBeBlockedBy` Flying/Reach), haste as `keywordAbility`, both granted to `Each` Sliver-creature-you-control. The FAIL is the rule's sibling over-reach, not the fixture.

**Under-guard evidence (not new mis-captures, but corroborating):** the `[A-Z][a-z]+` capture also treats Land (Tatyova, Halimar Tidecaller), Red (Bloodmark Mentor), Multicolored (Maze cycle), Tapped (Lost in the Maze), and Modified (Kodama, Temperamental Oozewagg) as subtypes. Those are single-keyword lines that `BareKeywordGrantRule` (967) already parses with the same `^(?<sub>[A-Z][a-z]+)\s+creatures?$` subtype-treatment, so the new rule reproduces pre-existing behavior there (out of scope for this batch's FAIL) — but they confirm the guard is insufficient.
