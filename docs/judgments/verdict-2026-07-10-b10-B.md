## FAIL verdicts

### mast-tdd/2026-07-10-nonartifact-enters-return (P10, Cloudstone Curio)
**Verdict:** FAIL
**Issue:** new relational axis `ObjectFilter.SharesPermanentTypeWith` is not registered in the interaction soundness floors.
**Rule citation:** CR 110.4 (the six permanent types) — modeling is fine; the defect is the missing floor registration.
**What the branch does:** adds `SharesPermanentTypeWith` to `ObjectFilter`, uses it in the fixture/parser, but does NOT add it to `ObjectFilterRelations.UndecidedAxis`, `ObjectFilterRelations.SupUndecidedAxis`, or `OperatorPropertyTests.IsRelational`. Those floors currently list `ExiledWith / SharesColorWith / SharesCreatureTypeWith / SharesNameWith / ChosenCharacteristic / History / AttachedTo` and stop there.
**Why this misrepresents the rule:** `UndecidedAxis` is documented as the soundness floor — "True if the filter constrains an axis the operator does not yet decide ... The residue is the Phase-3 relational axes." A filter whose membership depends on the entering permanent's *live* permanent types is exactly such an undecided relational axis; leaving it out means the operator treats the filter as fully decided/precise and can emit a wrong `Yes`/`No` overlap. Cloudstone Curio is a canonical infinite-bounce combo engine, so this silently corrupts the very loop-discovery MAST exists for. No hard test catches it (`FilterCoverageReportTests` is a diagnostic report, not an assertion).
**Suggested fix:** add a `SharesPermanentTypeWith is not null ? "SharesPermanentTypeWith"` arm to both `UndecidedAxis` and `SupUndecidedAxis`, and add it to `OperatorPropertyTests.IsRelational` — mirroring P08's `SharesCardTypeWith` handling.

**Rule text:** > 702.38 :: Amplify
**What the AST says:** `ObjectFilter.cs` field doc: "the card exiled by a linked Imprint ability (CR 702.38)"; and `ExileNonlandCardFromHandImprintTriggeredRule.cs`: "CR 702.38 (Imprint): an imprint ability exiles a card...".
**Why this misrepresents the rule:** citing the Amplify rule number on an Imprint node is a contradictory citation (the Fading-on-Kicker archetype).
**Suggested fix:** drop the two `CR 702.38` references; rely on CR 406.6 (already cited) for the imprint linked-ability shape, or note Imprint as a corpus gap (this CR extraction omits it). Everything else in P08 is sound — including the correct registration of `SharesCardTypeWith` in both soundness floors + `IsRelational`, and the incidental closing of the pre-existing `SharesNameWith` gap in `IsRelational`.
