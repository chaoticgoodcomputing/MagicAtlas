## Issues surfaced

### 1. Worktree-spawn staleness — the pre-flight gate fired correctly, but the underlying issue persists

Helper-novel manifest:
> Pre-flight note: Worktree was 263 commits behind main (script HALT condition: >20). Branch had zero unique commits, so resetting HEAD to main and creating the briefed branch was non-destructive.

The Step 0b pre-flight gate from batch #2 retrospective worked exactly as designed — it caught a worktree branched from a deeply stale ref. The agent self-recovered (hard reset with zero unique commits is safe). But this means **prior batches likely had worktrees silently branching from stale refs** without the gate to catch them — explaining recurring file leak-through and base-staleness symptoms in batches #1/#2.

**Action item:** The worktree-spawn mechanism (whatever orchestrator-side tool creates new worktrees for `Agent({ isolation: "worktree" })`) is spawning from a stale ref consistently. The gate is treating the symptom; the spawn flow is the disease. Investigating that is a separate session.

### 2. The keyword effect tail is still long

Top yield cluster after this batch is STILL `<KW>` (bare keyword line) at +56 cards. Surveying the new clusters list, we still need: `DeathtouchEffect`, `HexproofEffect`, `WardEffect`, `MorbidEffect`, others. The keyword-effect tail is wider than I expected.

**Recommendation for next batch:** another helper-novel run dedicated entirely to keyword effects. The pattern is now well-grooved (DefenderEffect/CascadeEffect are templates) — could land 8-10 new effect types in one helper-novel session.

### 3. Refuge-card cross-cluster coordination

KazanduRefuge / AkoumRefuge span clusters 1 (EntersTapped) and 4 (ETB lifegain). Both mechs needed to land before those cards could flip green. The two-mech coordination worked, but it's worth noting in the skill: **when fixtures span multiple in-flight clusters, both mechs' parser surfaces must land for the test to pass**. This isn't a problem here because the mechs are parallel-safe (different files), but it could become a problem with conflict-prone cluster pairs.
