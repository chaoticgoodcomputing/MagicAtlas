## FAIL verdicts

### tests/magic-ast-tests/Fixtures/HandParsedCards/SerendibDjinn.json  (K14)
**Verdict:** FAIL
**Issue:** "When you control no lands, sacrifice this creature" models the sacrifice `Target.Kind = It`, but the phrase is "this creature".
**Rule / doctrine:** AST `ObjectReferenceKind`: `Self` = "this creature", "this permanent"; `It` = "'it' — refers to a previously mentioned object".
**What the fixture says:** `{"EffectType":"sacrifice","Target":{"Kind":"It"}}`
**Why this misrepresents:** "this creature" is the ability's own source (Self). `It` is an anaphor requiring a previously-mentioned object, and there is none in this ability. Every precedent fixture with the literal phrase "sacrifice this creature" uses `Self` (LonghornFirebeast, WildLeotau, WhipstitchedZombie); only oracle "sacrifice **it**" maps to `It` (PhantasmalBear, FallowWurm, BalduvianHorde). FLAG-2 confirmed: the shared SacrificeTriggeredRule's `It` is the wrong reuse here.
**Suggested fix:** set the third ability's sacrifice `Target.Kind` to `Self`.
**Note (FLAG-1, not a FAIL):** the `ConditionalEffect{Condition:OtherCondition "you sacrifice an Island this way"}` free-text IS genuinely irreducible — a reflexive causation-gate (CR 603.12) + subtype filter on the object sacrificed by the ability's own preceding effect. No structured peer exists; it matches the whitelisted Spelunking precedent ("you put a Cave onto the battlefield this way"), whose peer rule `IfPutSubtypeOntoBattlefieldThisWayGainLifeRule.cs` exists on base. Damage source `Self`, target `You` correct. This component passes.

### libs/magic-ast/Parsing/Parsers/Triggered/Rules/ControlNoLandsConditionRule.cs  (K14)
**Verdict:** FAIL
**Issue:** Wrong-mechanic CR citation on a state-triggered ability.
**Rule citation:** doc cites **CR 603.2e** ("becomes" transition triggers); correct is **CR 603.8** (state triggers).
**Rule text:** > 603.8: "Some triggered abilities trigger when a game state (such as **a player controlling no permanents of a particular card type**) is true, rather than triggering when an event occurs." (603.2e instead governs "becomes attached/blocked/tapped/untapped … trigger only at the time the named event happens" — the opposite firing model.)
**What the file says:** `a state-triggered ability (CR 603.2e — a trigger that is a state condition; "when you control no [X]")`
**Why this misrepresents:** "When you control no lands" is textbook a state trigger (603.8; Serendib's own Gatherer ruling). 603.2e's text describes transition ("becomes") triggers that do NOT fire if the state already exists — contradictory to state-trigger semantics.
**Suggested fix:** cite CR 603.8 (state triggers). The modeling itself (`ControlNoLandType`, filter land/You/no-subtype) is correct.
