## New systemic issue surfaced

**Worktree file leak-through (same Data/ subdirectory shared between worktrees).** When a helper-mech worktree writes a file under `tests/magic-ast-tests/Data/HandParsedCards/` and the agent later bails on it (doesn't commit), the file persists in the main repo's working directory as an untracked file. Caused two merge interruptions this batch:

- First wave (helper merges): 7 untracked fixtures (`ECL/SpellSnare`, `GPT/Frazzle`, `SOM/HaltOrder`, `CHK/RendSpirit`, `CMD/Ruination`, `POR/VirtuesRuin`, `THS/DarkBetrayal`) blocked merge — all content-identical to the to-be-merged files, so removable.
- Second wave (mech merges): 1 untracked fixture (`NPH/MentalMisstep` — CounterSpell helper's bail) silently became a tracked test target and failed `Parser_ProducesExpectedOutput` post-merge.

Root cause: git worktrees share the same `.git` dir but have separate working trees. However, the `Data/` directory appears to be visible across worktrees (likely a shared filesystem mount or symlink in the worktree setup). The sub-agents' bail logic doesn't clean up partially-written files.

**Proposed fix:** Add a Step 0c cleanup step to the skill: before exit, sub-agents must `git -C "$WORKTREE_ROOT" clean -fd tests/magic-ast-tests/Data/HandParsedCards/` to remove any untracked files in the fixture directory. The orchestrator should also `git status` immediately after the pre-flight gate to verify no untracked HandParsedCards/* files leaked through from prior session.
