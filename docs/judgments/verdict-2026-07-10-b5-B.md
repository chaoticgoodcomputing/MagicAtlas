## FAIL verdicts

### J16 — libs/magic-ast/AST/Abilities/ObjectHasCardTypeCondition.cs (and AsLongAsEnchantedTypeKeywordGrantRule.cs)
**Verdict:** FAIL
**Issue:** Fabricated "verbatim" CR citation.
**Rule citation:** cited CR 611.2c — correct rule is CR 611.3a.
**Rule text (actual 611.2c):** > "If a continuous effect generated by the resolution of a spell or ability modifies the characteristics or changes the controller of any objects, the set of objects it affects is determined when that continuous effect begins. After that point, the set won't change."
**Rule text (correct, 611.3a):** > "A continuous effect generated by a static ability isn't 'locked in'; it applies at any given moment to whatever its text indicates."
**What the AST says:** doc-comment claims `CR 611.2c (verbatim): "If the effect is conditional ... the effect stops applying if the condition it's based on stops applying."`
**Why this misrepresents the rule:** That quoted text appears nowhere in the rules data (grep for "condition it" / "stops applying" confirms). Rune of Flight's "as long as enchanted permanent is a creature, it has flying" is a continuous effect from a STATIC ability (611.3), not from resolution (611.2). The real 611.2c says the affected-object set is LOCKED IN — the opposite of the continuously-reevaluated static grant the node models (611.3a).
**Suggested fix:** Citation-only. Replace `CR 611.2c` with `CR 611.3` / `611.3a` in both ObjectHasCardTypeCondition.cs and AsLongAsEnchantedTypeKeywordGrantRule.cs. The AST modeling is otherwise correct (structured quoted ability, correct card-type/subtype split, secondary lines parse) and would PASS.

### J02 — tests/magic-ast-tests/Fixtures/HandParsedCards/Anax.json
**Verdict:** FAIL
**Issue:** Self-inclusive "or another" trigger modeled as self-EXCLUDING.
**Rule citation:** CR 109.5 ("another" = excludes the ability's source).
**What the fixture says:** dies-trigger `Filter: { "CardTypes":["creature"], "IsToken":false, "Controller":"You", "ExcludeSelf":true }`
**Oracle text:** "Whenever Anax or another nontoken creature you control dies, ..."
**Why this misrepresents the rule:** "Anax OR another nontoken creature you control" INCLUDES Anax (a nontoken creature you control). `ExcludeSelf:true` drops Anax's own death, which the card explicitly triggers on. The established, consistent convention across every sibling models this WITHOUT ExcludeSelf — the exact structural twin Zulaport Cutthroat ("Zulaport Cutthroat or another creature you control dies") uses `{creature, Controller:You}` with no ExcludeSelf; likewise Blood Artist, Kalastria Highborn, High Perfect Morcant, Gonti's Aether Heart.
**Suggested fix:** Remove `ExcludeSelf:true` (self-inclusive filter `{creature, IsToken:false, Controller:You}`).
