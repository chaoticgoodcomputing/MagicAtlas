## Process notes (non-gating)

- **K15 wrong parenthetical citation.** `InstantAndSorcerySpellsCantBeCounteredRule`'s
  doc-comment justifies dropping the "spell" marker with "type disjunction
  (Rule 700.4)". In the rules dataset CR 700.4 is the **"dies"** definition, not a
  type-disjunction rule (no such numbered rule exists; disjunctive type references
  are natural-language). Not gated: the node's actual modeling is correctly grounded
  by CR 113.6g + CR 611.3 (the 700.4 ref is neither absent-at-rule-number nor
  contradictory to the modeling), but the citation should be dropped/replaced.

- **K15 filter-convention drift.** K15 uses `CardTypes:[instant,sorcery]` whereas the
  sibling `CreatureSpellsCantBeCounteredRule` uses `[spell,creature]` and K08/K18 in
  this same batch use `[spell,instant,sorcery]`. Same object set, but two encodings
  of "instant and sorcery spells you control" now exist. Recommend aligning K15 to
  `[spell,instant,sorcery]` for consistency (worker's "no spell marker needed on the
  stack" argument is defensible, hence non-gating).

- **K18 non-existent subrule.** `SelfNamePTForEachCounterYouHaveRule` cites
  "CR 122.2i experience counters specifically". CR 122.2 has no subrules; the correct
  grounding is CR 122.1 (also cited). Non-gating (parent concept correctly cited),
  but "122.2i" should be removed.

- **K18 latent name-matcher breadth (no current impact).** The `[Name] gets +N/+M for
  each <type> counter you have` matcher keys on a capitalised leading run + singular
  "gets"; it would also match "Each creature gets … counter you have" (→ Self, which
  would be wrong), but no such card exists in the corpus — the only self-name matches
  are Kelsien and Kalemne (Azula is correctly excluded by the end-anchor because of
  its trailing "and gains menace"). No actual over-capture; flagged for robustness.
