**Verdict:** FAIL
**Issue:** Nonexistent CR citation — the node's primary grounding rule (graveyard-functioning ability) is cited as CR 112.6a, which is absent from the rules data.
**Rule citation:** CR 112.6a (absent); correct is CR 113.6a / CR 113.6b
**Rule text:**
> 113.6a — "Characteristic-defining abilities function everywhere, even outside the game and before the game begins."
> 113.6b — "An ability that states which zones it functions in functions only from those zones."
(Rule 112 in rules-structure.json is titled "Spells" and contains only 112.1–112.4; there is no 112.6. Rule 113 is titled "Abilities" and is where zone-functioning lives.)
**What the AST says:** doc-comment: "CR 112.6a: an ability can function from a graveyard (or another zone) if it's written to do so or if the ability is characteristic-defining"
**Why this misrepresents the rule:** The cited number points at the Spells subsection, not the Abilities subsection, and 112.6a does not exist at all; the prose the comment quotes is verbatim the *concept* of 113.6a (characteristic-defining) + 113.6b (states which zones it functions in). Under the strict scope this is an absent-from-data citation (and a contradictory parent-rule number, 112 vs 113 — not a subrule-letter slip), which is a FAIL.
**Note:** The *modeling* is otherwise sound — the first conjunct (CountCondition{Filter: IsSelf + Zone.Graveyard, >=1}) composed with "you control a Forest" via AllCondition under an AsLongAsDuration on GainAbilityEffect(trample) is a faithful, structured, describe-not-execute representation, and the co-cited CR 702.19a ("Trample is a static ability") is correct. Only the graveyard-zone citation is wrong.
**Suggested fix:** Change the doc-comment citation from "CR 112.6a" to "CR 113.6a / CR 113.6b" (characteristic-defining / states-which-zones-it-functions-in). No AST/fixture change needed. (The paired fixture Brawn.json is itself correct and passes.)
