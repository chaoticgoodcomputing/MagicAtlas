## Process notes

- **No new discriminators this shard.** All five families reuse existing effect types (`tap`/`doesntUntap`/`addMana`/`gainAbility`/`putCounters`/`keywordAbility`/`searchLibrary`), an existing trigger event (`TapsForMana`, `GainsLife`), and pre-existing keyword enums (`Infect` from batch-7, `Prepared` from MB5-KW7). The initiative-03 exhaustiveness ratchet therefore requires no new PortWalk projection entries here, and there is nothing insensible to fail.
- **TapAll / UntapAll type-vs-subtype coarseness (pre-existing, shared).** `TapAllTriggeredRule`'s `(?<type>[a-z]+)`→CardTypes maps a *subtype* noun ("Islands", "Merfolk", "Spirits") into `CardTypes` rather than `Subtypes`. This is IDENTICAL to the established `UntapAllTriggeredRule` sibling — the new rule mirrors it exactly rather than introducing a novel mislabel — and no gold fixture in this batch exercises the subtype path (the only fixture, Wrath, is `red creatures` → `creature`, correct). Flagged for the family-level engine-lens sweep, not a batch FAIL.
- **SearchLibrary single-pattern disjunction-unawareness (pre-existing class).** When an `X or Y` disjunction where the tokens are subtypes (not card types) falls through the guarded `_orPattern` into the single `_pattern`, the connective "or" is captured as a stray subtype. This is the SAME behavior the single pattern already had for the "a X or Y" article forms (Caradora, Lo and Li, Analyze the Pollen); the `an?` widen merely makes it reachable for the "an" article. The batch's own new structured path (`_orPattern`) is correct and guarded. Not a batch-introduced regression class; noted for a future disjunction-aware single-pattern pass.
