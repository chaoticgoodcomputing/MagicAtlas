## Family 1: (LordPowerToughnessBuff, StaticAbilityParser.Parse) — 639 cards

**Failure signal:** parser bails for 639 cards in this cluster. The shape is `[FilterDescription] (get|gets) +N/+N` — a lord effect granting P/T to a filtered set of creatures the controller controls (or globally).

### Cards in this family
1. **Dralnu's Crusade** — `All Goblins get +1/+1.`
2. **Myr Matrix** — `Myr creatures get +1/+1.`
3. **Night of Souls' Betrayal** — `All creatures get -1/-1.`
4. **Soraya the Falconer** — `Bird creatures get +1/+1.`
5. **Thelonite Hermit** — `All Saprolings get +1/+1.`
6. **Chainer, Dementia Master** — `All Nightmares get +1/+1.`

### Relevant rules
- **Rule 613.1c (Continuous effects)** — power and toughness modifications apply in layer 7C.
- **`ModifyPTEffect`** (existing, `[OracleEffect("modifyPT")]`) — `Target: ObjectReference`, `PowerModifier: Quantity`, `ToughnessModifier: Quantity`. Used by `AsLongAsCondition` family for self-PT mods; this family extends it to filter-targets.
- **`ObjectReference`** with `Kind: Each` (existing) handles "All [filter]". Filter can be Subtypes-only (`Goblins`, `Nightmares`, `Saprolings`), CardTypes-only (`creatures`), or both (`Bird creatures`, `Myr creatures`).

### Expected generalization
ONE static-rule recognizer: `^(All\s+)?<filter>\s+(get|gets)\s+([+-]\d+)/([+-]\d+)\.?$`. Filter parsing:
- Bare subtype ("Goblins", "Saprolings") → `Subtypes: [singular]` (drop 's')
- "X creatures" → `CardTypes: ["creature"], Subtypes: [X]` (if X is a subtype like "Bird", "Myr")
- "All creatures" → `CardTypes: ["creature"]`
- Negative modifiers (`-1/-1`) work via NegativeLiteralQuantity or LiteralQuantity with negative value — check existing convention.

### Anti-patterns
- Don't conflate with `AsLongAsCondition` family — that's a separate suffix-peel concern. If the line has `as long as`, leave it to the AsLongAs parser.
- Don't recurse into "creatures you control" (that's a different filter — Controller predicate). Some Lord-effect cards have implicit "creatures you control" semantics from card position; the oracle text doesn't always say it explicitly. Trust the oracle text.

None.

## Family 2: (AttackTrigger, TriggeredAbilityParser.Parse) — 227 cards

**Failure signal:** parser bails on triggered abilities of the form `(When|Whenever) <subject> attacks, <effect>`.

### Cards in this family
1. **Ghalta and Mavren** — `Whenever you attack, choose one —` (modal — may need bail if modal-trigger combo is novel)
2. **Svyelun of Sea and Sky** — `Whenever Svyelun attacks, draw a card.`
3. **Winter, Cynical Opportunist** — `Whenever Winter attacks, mill three cards.`
4. **Radha, Heir to Keld** — `Whenever Radha attacks, you may add {R}{R}.`
5. **Coram, the Undertaker** — `Whenever Coram attacks, each player mills a card.`

### Relevant rules
- **Rule 603 (Triggered abilities)** — same as BeginningOfTurnTrigger family.
- **Rule 508 (Declare Attackers)** — "attacks" trigger fires when the creature is declared as an attacker.
- **`TriggerEvent.Attacks`** (existing) — direct enum value.

### Expected generalization
Extend `TriggeredAbilityParser.ParseTriggerCondition` (or the analogous method) to recognize:
- `Whenever you attack` → `TriggerCondition { Timing: Whenever, Event: Attacks, Filter: { Controller: You } }` (you-as-controller attacking with anything)
- `Whenever <CardName> attacks` → `TriggerCondition { Timing: Whenever, Event: Attacks, Filter: { ObjectReference: Self / NameMatch } }` (self-attack trigger)
- The effect after the comma delegates to existing effect cascade.

### Anti-patterns
- Don't add a new TriggerEvent value — `Attacks` already covers it.
- `you attack` is NOT the same as `<self> attacks` — the former triggers on ANY creature you control attacking; the latter triggers on this specific permanent attacking. Encode the distinction in the Filter slot.
- Bail (don't force) if a fixture is `attacks with X and another Y` — that pattern was already added by the AsLongAs mech last batch for Merry. Check `TriggeredAbilityParser.cs` for `TryParseAttackWithAndAnotherTrigger` before assuming.
- Modal-triggered fixtures ("Whenever you attack, choose one —") may need a Modal-effect-cascade integration — bail if the modal options aren't already supported by existing effect parsers.

### Glossary gaps
None.

## Family 3: (CounterSpell, SpellAbilityParser.SpellTapTargetRule) — 111 cards

**Failure signal:** no spell rule yet for `Counter target <filter> spell` shapes (plus condition variants).

### Cards in this family
1. **Frazzle** — `Counter target nonblue spell.`
2. **Halt Order** — `Counter target artifact spell.`
3. **Mental Misstep** — `Counter target spell with mana value 1.`
4. **Spell Snare** — `Counter target spell with mana value 2.`
5. **Ertai's Trickery** — `Counter target spell if it was kicked.` (conditional — may need bail)
6. **Spell Burst** — `Counter target spell with mana value X.` (variable — check Quantity convention)

### Relevant rules
- **Rule 701.5 (Counter)** — "To cancel a spell or ability so it doesn't resolve and none of its effects occur. The countered spell is put into its owner's graveyard."
- **`CounterSpellEffect`** (existing, `[OracleEffect("counterSpell")]`) — `Target: ObjectReference` field.

### Expected generalization
ONE new `[SpellRule(Priority = 60)]` file `Spell/Rules/CounterSpellRule.cs`. Matches `^Counter target (?<filter>.+?) spell( with mana value (?<mv>\d+|X))?\.?$`:
- Bare filter ("nonblue", "artifact", "instant or sorcery") → Characteristics or CardTypes
- "with mana value N" → ObjectFilter has a slot for this (check `libs/magic-ast/AST/References/ObjectFilter.cs`); if not, add it via Characteristics: ["mana value N"] free-text escape hatch
- "with mana value X" → similar, with `X` as the value (LiteralQuantity? VariableQuantity? Check existing CounterSpellEffect users)
- BAIL on conditional shapes ("if it was kicked", "if you control a snow land") — those need separate ConditionalCounterSpell handling.

### Anti-patterns
- Don't invent a `ManaValueFilter` type if `ObjectFilter` doesn't have it — use `Characteristics: ["mana value N"]` per existing escape-hatch convention.
- The target is a SPELL on the stack, not a permanent. `ObjectReferenceKind: Target` with the appropriate filter scope.

### Glossary gaps
None.

## Family 4: (DestroyTargetSpell residual, SpellAbilityParser.SpellTapTargetRule) — 252 cards

**Failure signal:** the existing `DestroyAllRule.cs` (landed last batch) handles `Destroy all <bare-filter>` only. The 252 residual cards are mass-destroy or target-destroy with **richer filters** the rule doesn't support.

### Cards in this family
1. **Rend Spirit** — `Destroy target Spirit.` (subtype-only, no "creature" word)
2. **Ruination** — `Destroy all nonbasic lands.` (non-prefix)
3. **Virtue's Ruin** — `Destroy all white creatures.` (color + type)
4. **Maelstrom Artisan // Rocket Volley** — `Destroy target nonbasic land.` (non-prefix on target)
5. **Dark Betrayal** — `Destroy target black creature.` (color + type on target)
6. **Planar Outburst** — `Destroy all nonland creatures.` (non-prefix)

### Relevant rules
Same as Family 3 (DestroyTargetSpell last batch).

### Expected generalization
**Extend** the existing `Spell/Rules/DestroyAllRule.cs` AND the existing `Spell/Rules/DestroyTargetSimpleRule.cs` (the latter likely exists — check) to support these filter dimensions:
- **Subtype-only** ("Spirit", "Human") → `Subtypes: [X]`
- **Color predicate** ("white", "black", "nonblue") → `ColorPredicate` slot (check `ObjectFilter`) OR `Characteristics: ["white"|"black"|"nonblue"]`
- **non- prefix** ("nonbasic", "nonland", "nonblue") → `Characteristics: ["nonbasic"|"nonland"|"nonblue"]`
- **Combined** ("black creature", "Human creature") → multiple filter slots populated

If the two existing rules can both share a helper for filter parsing, extract it (under `Spell/SpellRuleHelpers.cs` perhaps). Don't write a new `DestroyByColorRule.cs` — that's family-contract drift.

### Anti-patterns
- Don't create a third Destroy rule. Either extend `DestroyAllRule` for new "all" variants OR extend `DestroyTargetSimpleRule` for new "target" variants, NOT both.
- The shape `(All | Target)` is the existing branching — the residual cards fit existing branches, they just need richer filters.

### Glossary gaps
None.

## Family 5: (ReturnTargetSpell residual, SpellAbilityParser.SpellTapTargetRule) — 158 cards

**Failure signal:** existing `ReturnTargetToHandRule.cs` handles `Return all/target X to their owners' hands`. Residual cards have additional dimensions.

### Cards in this family
1. **Failure // Comply** — `Return target spell to its owner's hand.` (target SPELL, not permanent)
2. **Galestrike** — `Return target tapped creature to its owner's hand.` (tapped-state predicate)
3. **Hibernation** — `Return all green permanents to their owners' hands.` (color predicate + permanent)
4. **Inundate** — `Return all nonblue creatures to their owners' hands.` (non-color + creature)
5. **Auroral Procession** — `Return target card from your graveyard to your hand.` (graveyard zone, your-hand destination)

### Relevant rules
Same as ReturnTargetSpell last batch.

### Expected generalization
**Extend** `Spell/Rules/ReturnTargetToHandRule.cs` to support:
- **Target spell** → `ObjectReferenceKind: Target` with scope=stack (check `ObjectReference.Zone` or similar). Different from target permanent.
- **Tapped state** ("tapped creature") → `Characteristics: ["tapped"]` free-text
- **Color predicate** ("green permanents", "nonblue creatures") → same approach as DestroyTargetSpell residual
- **Source zone** ("from your graveyard") → `ObjectFilter.Zone` if exists, else `Characteristics`
- **Destination** ("to your hand" vs "to its owner's hand" vs "to their owners' hands") — `ReturnToHandEffect` may need a Destination slot. Check the type first; if missing, BAIL — that's a novel AST change, not mechanical.

### Anti-patterns
- Don't repeat the WUBRG ordering bug from last batch — `colorIdentity` arrays must be canonical-ordered (well, the comparator now treats them as set-semantic, but emit WUBRG for readability).
- "your hand" vs "owner's hand" is a real distinction — owner is the player who originally cast the card; you-as-controller might not be the owner.
- BAIL if `ReturnToHandEffect` has no destination slot — that's a novel AST shape, not for this mech.

### Glossary gaps
None.
