## CONCERN verdicts

### `libs/magic-ast/AST/Effects/Core/ModalEffect.cs`
**Verdict:** CONCERN
**Issue:** Rule citation cites parent rule (700.2) when subrule (700.2b) is more precise for the triggered-modal case the node is designed to model.
**Rule citation:** 700.2b
**Rule text:** > "The controller of a modal triggered ability chooses the mode(s) as part of putting that ability on the stack."
**What the AST says:** Doc-comment cites "Rule 700.2 — modal preamble."
**Why this is a CONCERN:** 700.2 introduces the modal concept generally; the triggered-ability variant — which is exactly what this node was built for (Ao, the Dawn Sky's death-trigger preamble) — is 700.2b. Generic 700.2 covers it but loses precision.
**Suggested fix:** Tighten the cite in `ModalEffect.cs`'s doc-comment to "Rule 700.2 (modal preamble); see 700.2b for triggered-modal specifically."

### `libs/magic-ast/AST/Effects/Keyword/KeywordReferenceEffect.cs`
**Verdict:** CONCERN
**Issue:** Intentional structural escape hatch — a string-typed keyword reference inside the otherwise-typed AST.
**Rule citation:** N/A (the node doesn't claim a specific rule).
**Why this is a CONCERN:** Holds keyword name as raw string. Recovers descriptive intent (the granted ability IS named `"suspend"`), but every use of `KeywordReferenceEffect` is a marker for "promote this keyword to a first-class effect." Acceptable as a deliberate escape hatch per the orchestrator's framing; not BLOCKING because the node's doc-comment is explicit about its placeholder role.
**Suggested fix:** None this batch. Track promotions: Suspend (Rule 702.62) is the live deferral; Morph, Adapt, Bestow, etc. would land here too unless promoted first.

### `tests/magic-ast-tests/Data/HandParsedCards/FDN/FindThePath.json`
**Verdict:** CONCERN
**Issue:** `AffectedObjects.Characteristics: ["enchanted land"]` uses free-text where the AST already has structural axes for the same concept.
**Rule citation:** Rule 702.5 Enchant
**Rule text:** > "If [an Aura's enchant ability] specifies what kind of object can be enchanted, the Aura can only be attached to legal objects."
**What the fixture says:** `"AffectedObjects": { "Characteristics": ["enchanted land"] }`
**Why this is a CONCERN:** The "enchanted land" phrase is structurally redundant with `Target.Kind == EnchantedOrEquipped` already on the effect — the AffectedObjects filter adds nothing the target reference doesn't already say. The other axes (`CardTypes`, `Subtypes`) are available for type-narrowing if it's wanted.
**Suggested fix:** Either drop `AffectedObjects` entirely (the Target reference is sufficient) or replace `Characteristics: ["enchanted land"]` with `CardTypes: ["land"]`. Defer to a future audit-driven fixture migration; not BLOCKING because the descriptive intent is preserved.

### `tests/magic-ast-tests/Data/HandParsedCards/OGW/CeremoniousRejection.json`
**Verdict:** CONCERN
**Issue:** `Colors: ["C"]` encodes "colorless" as a color value, which is structurally awkward.
**Rule citation:** Rule 105.1 (Colors)
**Rule text:** > "Colorless is not a color."
**What the fixture says:** `"Colors": ["C"]` on `ObjectFilter`, denoting a colorless spell target.
**Why this is a CONCERN:** Per CR 105.1, colorlessness is the *absence* of all colors, not a color value. Modeling it as `Colors: ["C"]` works as a convention (the agent reports this matches existing `TriggeredAbilityParser` color handling) but pulls semantically against the rule. An explicit `IsColorless: bool` flag or empty-colors-means-colorless convention would be sharper.
**Suggested fix:** Out of scope for this batch — the encoding is consistent with existing precedent. Worth a structural decision in the next audit pass; not BLOCKING because the convention is in use elsewhere in the codebase and works descriptively.

### `tests/magic-ast-tests/Data/HandParsedCards/WHO/RoryWilliams.json`
**Verdict:** CONCERN
**Issue:** The granted "suspend" keyword is modeled via `KeywordReferenceEffect` instead of a first-class `SuspendEffect`.
**Rule citation:** Rule 702.62 Suspend
**Rule text:** > "Suspend is a keyword that represents three abilities. The first is a static ability that functions while the card with suspend is in a player's hand…"
**What the fixture says:** `GainedAbility.Effect: { "EffectType": "keywordReference", "Keyword": "suspend" }`
**Why this is a CONCERN:** Same as the `KeywordReferenceEffect` node concern — intentional escape hatch documented by both the node and the agent's manifest. Suspend is a complex keyword (Rule 702.62 has many subrules); promoting it deserves its own focused batch.
**Suggested fix:** Promote Suspend to a first-class `SuspendEffect` in a future batch. The migration is mechanical once the type exists.
