## Candidate 1: Ceremonious Rejection (ComplexTargeting)

**Oracle:** "Counter target colorless spell."
**Card:** `Ceremonious Rejection` — Commander-legal paper printing (OGW, MH3).

### Relevant rules
- **Rule 701.6 Counter** (701.6a): *"To counter a spell or ability means to cancel it, removing it from the stack. It doesn't resolve and none of its effects occur. A countered spell is put into its owner's graveyard."*
- **Glossary "Counter"** (the verb sense): "To cancel a spell or ability so it doesn't resolve and none of its effects occur. See rule 701.6, 'Counter.'"
- **Rule 105** (colorless) — colorless is a property checkable on a spell. Color filters in MAST belong on `ObjectFilter.Colors` (or its complement).

### Anti-patterns
- Don't model "colorless" as a free-text `Characteristics` entry — colors are a structured filter axis. Either extend `ObjectFilter.Colors` semantics (empty list = colorless?) or add an explicit `IsColorless` flag, but pick a structural representation.
- Don't model counter as a sub-effect of the targeted spell. Counter is a primitive — it targets the spell directly.

## Candidate 2: The Foretold Soldier (ConditionalEffect)

**Oracle line of interest:** "This creature must be blocked if able."
**Card:** `The Foretold Soldier` (or similarly-shaped vanilla creature with the line — agent's choice).

### Relevant rules
- **Rule 509.1c** (Declare Blockers Step): *"The defending player checks each creature they control to see whether it's affected by any requirements (effects that say a creature must block, or that it must block if some condition is met). If the number of requirements that are being obeyed is fewer than the maximum possible number of requirements that could be obeyed without disobeying any restrictions, the declaration of blockers is illegal."*
- **Glossary "Block"**: "To send a creature into combat defensively. A creature can block an attacking creature. See rule 509, 'Declare Blockers Step.'"
- **Symmetry with batch 2**: `MustAttackEffect` (Rule 508.1d) was added in batch 2 for Zurgo — `MustBeBlockedEffect` is the dual-side counterpart on Rule 509.1c. Follow the same shape unless the rule asymmetry argues otherwise.

### Anti-patterns
- Don't reuse `EvasionEffect` — this is a *requirement* (must be blocked), not a *restriction* (can/can't be blocked). They're different sides of the same rule machinery and conflate badly under one node.
- The effect target is `[Self]`, not the attacker. The card's controller is saying "*this creature*, the one this ability is on, must be blocked." Model the subject as `ObjectReference.Self()`.

### Glossary gaps
None.

## Candidate 3: Find the Path (NestedAbility)

**Oracle line of interest:** "Enchanted land has '{T}: Add {G}{G}.'"
**Card:** `Find the Path` — Aura-style permanent grants a mana ability to the enchanted land.

### Relevant rules
- **Rule 605 Mana Abilities** (definition): an activated or triggered ability that could create mana and doesn't use the stack.
- **Rule 113.3b Activated Abilities**: "[Cost]: [Effect.] [Instructions.]"
- **Rule 113.6 / 113.10** — abilities granted by an effect are still abilities of the object they're granted to. The granted ability is itself an `ActivatedAbility` with its own `Costs` (TapCost) and `Effects` (AddManaEffect).
- **Rule 702.5 Enchant** — for context, this card is an Aura attached to a land. "Enchanted land" is the reference target.
- **Glossary "Aura"**: "An enchantment subtype. Aura spells target objects or players, and Aura permanents are attached to objects or players. See rule 303."

### Anti-patterns
- The current `GainAbilityEffect.AbilityText: string` field is the smell here. The audit recommends promoting this to a typed `Ability` node. Use the structured `ActivatedAbility` shape inside the grant, not the free-text string.
- `Enchanted land` is the reference target — use `ObjectReferenceKind.EnchantedOrEquipped` (already exists).

### Glossary gaps
None.

## Candidate 4: Mishra's Helix (VariableEffect)

**Oracle line of interest:** "{X}, {T}: Tap X target lands."
**Card:** `Mishra's Helix` — variable-X activated ability where the same X both pays the cost and counts the targets.

### Relevant rules
- **Rule 107.3 X**: "If a player is instructed to choose a value for X, that player may choose any value of 0 or greater unless the spell or ability specifies otherwise."
- **Rule 107.3b/c** — X in costs and X in effects refer to the same chosen value when both appear in the same activated ability.
- **Rule 113.3b** — activated ability shape: cost (`{X}, {T}`) → effect (`Tap X target lands`).

### Anti-patterns
- The X in cost and the X in effect must be the **same** Quantity instance descriptively (i.e., the same `VariableQuantity { Name: "X" }`). Both serialize to the literal "X" because they reference the same chosen value at activation.
- Tap effect target is `X target lands` — that's a target *set* of size X. Look at `Quantity` polymorphic options (`VariableQuantity`, `UpToQuantity`) and check whether `ObjectReference` carries a quantity at all today. If not, a `Quantity` field on the target may need to land — or the existing `Quantity` on `TapEffect` may already support it.

### Glossary gaps
None.

## Candidate 5: Ao, the Dawn Sky (UnparsedTriggered)

**Oracle line of interest:** "When Ao dies, choose one —"
**Card:** `Ao, the Dawn Sky` — death-trigger preamble for a modal ability. Full card has bulleted option list after the preamble.

### Relevant rules
- **Rule 603.2** — triggered ability fires once each time its trigger event occurs.
- **Rule 603.6c (death triggers)**: "Triggered abilities that trigger when a permanent dies trigger when the permanent is put into a graveyard from the battlefield."
- **Glossary "Die"**: "A creature or planeswalker that's put into a graveyard from the battlefield dies. See rule 700.4, 'Dies.'"
- **Rule 700.4 Dies**: a permanent dies when it goes from the battlefield to its owner's graveyard.
- **Modal preamble (Rule 700.2)**: "If a spell or ability has the modal text 'choose one,' 'choose one or more,' or similar, the choices that may be made are listed in a bulleted list."

### Anti-patterns
- The trigger event is `Dies` (already exists in `TriggerEvent`). The trigger filter targets `Self`. The trigger condition is the entire `When Ao dies` preamble.
- The "choose one —" continuation makes this **modal triggered** — the trigger's `Effects: List<Effect>` should be a single `ModalAbility`-shaped wrapper, NOT a flat option list directly under the trigger. Look at how Modal options are currently modeled in `RoadOfReturn.json` (Spell modal) for the existing pattern; the same shape applies but wrapped inside a `TriggeredAbility`.

### Glossary gaps
None — `Die`, `Modal`, and `Choose One` are all rules-defined.
