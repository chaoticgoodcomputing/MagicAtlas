## Systemic issues to address

### 1. WUBRG color-ordering errors recurring in helper-mech fixtures (3 caught)

Three fixtures landed with non-WUBRG `colorIdentity` ordering:
- `SupremeVerdict.json` — `[U,W]` should be `[W,U]` (caught by Destroy mech's bail)
- `MerryEsquireOfRohan.json` — `[R,W]` should be `[W,R]` (caught by AsLongAs mech)
- `CallOfTheConclave.json` — `[G,W]` should be `[W,G]` (my own fixture, caught by CreateToken mech)

`AttributeExtractor.ComputeColorIdentity` emits canonical WUBRG always; fixtures must match. The helper-mech prompt should include an explicit color-ordering reminder, OR the helper agents should run a colorIdentity validation pre-commit.

**Proposed skill update:** Add to the [sub:helper-mech] prompt's anti-patterns: "ColorIdentity arrays MUST be WUBRG-ordered (W → U → B → R → G), NOT alphabetical. Colors arrays use the Scryfall input order (alphabetical). Mismatch is a guaranteed parser-mech bail." Or alternatively, build a `tests/magic-ast-tests/Data/HandParsedCards/.validate` script that checks ordering and fails the test.

### 2. Family-contract scope creep on multi-ability fixtures (3 mechs)

Three mechs touched out-of-family code to make full-card tests pass:
- **AsLongAs mech** added `attack with X and another` trigger (Merry's sibling ability) to `TriggeredAbilityParser.cs`
- **CreateToken mech** added `InvestigateSpellRule.cs` + `AbilityClassifier` expansion (HardEvidence's `Investigate.` line)
- **BeginningOfTurn mech** added 3 activated-parser extensions (Broodheart's activated ability with activation restrictions)

The family contract assumes one card has one ability shape from the family. Real fixture cards are multi-ability; making `Parser_ProducesExpectedOutput` pass requires solving siblings too. Each mech faced a binary choice:
- BAIL on the multi-ability card (leaving the family partially done), or
- Solve the sibling abilities (scope-creep)

All three chose option 2. Defensible — each scope expansion was a real parser gap and the work was tightly scoped. But it weakens the family-contract discipline.

**Proposed skill updates** (one or more):
- (a) Permit sibling-ability parser work when it's a single-shape addition and doesn't conflict with another active family.
- (b) Require the orchestrator to pre-curate fixtures to single-family multi-ability or single-ability cards (more upfront work).
- (c) Allow split branches: mech solves family fully, then sibling-fixes go to a separate "remediation" sub-agent.

(a) matches what the mechs did naturally and is the lowest-friction option.

### 3. Worktree base-staleness recurred (Mermaid agent)

The Mermaid sub-agent's worktree was branched from commit `6b1db77` ("fix: python cache issues" — far back), never rebased. Its modifications to `Catalog.cs`, `Program.cs`, `MagicAstTriageFlow.cs` would have reverted the rule-split, FallbackParser refinement, and helper-mech fixture work if merged. The mandatory Step 0 rebase did not happen — same recurring issue called out in the prior 10-batch summary.

Salvage: extracted the 2 standalone Mermaid files (`MermaidEmitter.cs`, `EmitFixtureGraphsStep.cs`) onto main with one trait-interface fix to compile. Wiring deferred. The agent's stale baseline was visible in its closing manifest ("58 pass / 62 fail" — pre-rule-split numbers; "Per-fixture count: 25" vs current 94).

**Proposed fix:** A hard pre-flight gate at sub-agent worktree spawn that aborts if `git merge-base HEAD main` is not within the last N commits. Currently the Step 0 instruction is text-only and clearly insufficient.

### 4. Bloodcurdler fixture should have been bailed at helper stage

Bloodcurdler has 3 abilities: Flying (helper-mech's primary), BeginningOfUpkeep mill (family), Threshold static (out of scope). The helper-mech wrote full gold for all 3 instead of bailing. The parser-mech then correctly bailed on the Threshold portion, but the fixture itself was unmergable as-is (RoundTrip green but Parser_ProducesExpectedOutput red).

The helper-mech bail criterion ("BAIL if you'd need a new AST type") didn't fire here because Threshold uses only existing AST types — it's the PARSER that's missing the shape, not the AST. Helper-mechs should also bail on cards whose siblings would require parser work beyond the assigned family's scope.

**Proposed skill update:** Expand helper-mech bail criteria from "needs new AST type" to "needs new AST type OR needs sibling parser work beyond the assigned family's scope." The helper-mech should run `nx run mast:test` to check `Parser_ProducesExpectedOutput` for the fixture — if other-family ability shapes are unparseable, BAIL.

## What I'd do differently next batch

- Pre-curate fixtures more aggressively to single-family cards (using corpus-wide regex on oracle text).
- Build a `mast:setup-worktree` nx target that rebases + verifies main-currency, called by every sub-agent's Step 0 instead of trusting prompt instructions.
- Skip the formal judge dispatch when the issues are orchestrator-level. Save judge for batches with novel-shape helper-novel work (where rules-accuracy matters).
