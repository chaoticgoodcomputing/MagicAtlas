## Briefing scope corrections (helper-novel made the right calls)

The briefing called for 14 effects; helper-novel landed 10. The 4 deferrals were all legitimate:

1. **First strike / Double strike** — already covered by existing `CombatDamageTimingEffect { Timing: First | Both }`. Briefing's audit step missed this collision. Helper-novel checked before duplicating.
2. **Ward** — already partially modeled in `StaticAbilityParser.TryParseWardKeyword` as a triggered ability with `CounterSpellEffect + UnlessClause`. Replacing it with a flat `WardEffect { Cost }` is a refactor (touches parser + fixture + glossary), not a helper-novel add. Deferred to a dedicated Ward-refactor session.
3. **Kicker** — every Kicker oracle line has a paired "If this spell was kicked, …" conditional. No existing AST wraps an effect in a "spell-was-kicked" condition; that's a new schema axis. Landing `KickerEffect` without fixtures would be dead code. Deferred to a session that introduces the kicked-conditional shape.

This is exactly the kind of audit-before-action the keyword-sweep approach was designed for. The agent surfaced collisions the orchestrator missed; the corrections were sound.

## Issues surfaced

### 1. Worktree base-staleness — still recurring

Helper-novel's pre-flight gate fired AGAIN ("Worktree was 274 commits behind main"). Auto-recovered. **Third batch in a row this has happened.** The pre-flight gate is working as designed, but the spawn flow is consistently giving stale worktrees. This is a real architectural issue with the worktree creation mechanism, not a per-batch annoyance.

### 2. GLOSSARY.md leak-through (new variant of the worktree leak issue)

When helper-novel ran `nx run magic-ast:glossary` in its worktree, the regenerated `libs/magic-ast/GLOSSARY.md` appeared as a modified file in main's working directory too — blocking the merge with "local changes would be overwritten." Discarded the working-tree change; the helper's branch had the correct committed version. Same pattern as the `Data/HandParsedCards/` leak-through from batch #2, but for a different file.

Suggests worktrees share more of the filesystem with main than expected. Worth tracking down what exactly is shared (symlinked? unioned?) — affects which directories are safe to write to vs. which leak.

### 3. The composite-effect cluster is the new frontier

Two of the new top-5 clusters are "X gets +N/+N AND has/gains KEYWORD" composites. The existing AST has `CompositeEffect` (visible in the GLOSSARY) — needs a parser surface that detects the "X and Y" effect-conjunction shape on a static line. That's not a missing AST type, it's a missing parser rule. Mechanical session.
