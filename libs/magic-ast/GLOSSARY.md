## `/AST/Effects/Keyword/`

### `BandingEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

Banding (Rule 702.22). A legacy keyword ability that modifies rules for declaring attackers and assigning combat damage: creatures with banding can attack in a band, blocking creatures in a band are treated as a group, and the attacking or blocking player divides combat damage among blocking/attacking creatures with banding. MAST records the keyword's presence; the combat-step rule modifications are engine territory.

The related "Bands with other [quality]" variant is not modeled by this effect — it carries a quality parameter and should land as a future refinement when corpus pressure warrants.

- **Effect discriminator:** `banding`

[Source](AST/Effects/Keyword/BandingEffect.cs)

### `BestowEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

Bestow (Rule 702.103). "If you cast this card for its bestow cost, it's an Aura spell with enchant creature. It becomes a creature again if it's not attached." MAST records the keyword's presence and the bestow cost; the alternative-cost / Aura-mode / unattach semantics are conventionally inferred from the rules (per the descriptive-not-engine doctrine), mirroring the EquipEffect and CyclingEffect patterns.

`Cost` is the polymorphic base type for parity with the other cost-bearing keyword effects (Equip, Cycling) — most printings use a `ManaCost`, but the base accommodates future variants.

- **Effect discriminator:** `bestow`

[Source](AST/Effects/Keyword/BestowEffect.cs)

### `BushidoEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

Bushido (Rule 702.45). A triggered keyword ability printed as "Bushido N (Whenever this creature blocks or becomes blocked, it gets +N/+N until end of turn.)". Although Bushido is mechanically a triggered ability, MAST records it as a keyword marker — same approach as Prowess, Exalted, Cascade — and treats the canonical trigger-and-buff expansion as engine territory.

- **Effect discriminator:** `bushido`

Crew effect: this Vehicle becomes an artifact creature until end of turn if a total power of N or more of other creatures is tapped to crew it. "Crew N" — Rule 702.122. The oracle keyword reads "Crew N" and expands to an activated ability whose cost is tapping any number of other untapped creatures with total power N or more. MAST records only the keyword's presence and its parameter; the cost-and-resolution machinery is engine territory, not described by the oracle line itself.

### `CyclingEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

Cycling (Rule 702.32). An activated ability functioning only in hand: "[Cost], Discard this card: Draw a card." MAST records the keyword's presence and the cycling cost; the inner discard/draw structure is conventionally inferred from the rules.

Describes an effect whose oracle text carries a duration clause — e.g., "until end of turn", "until your next turn", "as long as you control...". The trait captures the *presence* of such a clause; the actual scoping rules are a runtime concern handled by consumers of the AST.

MAST is not a rules engine — this trait describes what the card text says, not when the effect actually ends in play.

[Source](AST/Effects/Traits/IDurativeEffect.cs)

### `IOptionalEffect` — *interface*

Describes an effect that the controller may choose whether to perform (the "You may..." prefix in oracle text). The optional follow-up `IfYouDo` captures the "If you do, [Y]" continuation pattern where a secondary effect is contingent on the controller having chosen to perform the main effect.

This trait describes *what the card text says*, not how/when the decision is resolved at runtime — MAST is not a rules engine.

[Source](AST/Effects/Traits/IOptionalEffect.cs)

### `IPreventableEffect` — *interface*

Describes an effect whose oracle text carries an "unless [player] pays [cost]" clause — a syntactic pattern where the effect can be prevented by paying a stated cost. Common on cards like Rhystic Study, Mystic Remora, and Ward.

This trait records the *presence and shape* of the unless clause in oracle text. The decision-and-payment workflow is a runtime concern for consumers of the AST — MAST is not a rules engine.

[Source](AST/Effects/Traits/IPreventableEffect.cs)

## `/Parsing/`

### `IAbilityParser` — *interface*

Contract for an ability-kind-specific parser. Each implementation handles one `AbilityKind` and is discovered at startup by `AbilityParserRegistry` via an `OracleAbilityParserAttribute` decoration. ## `/Parsing/Parsers/Spell/`

### `IMultiSpellRule` — *interface*

Extension of `ISpellRule` for shapes that expand to a flat list of effects on `Effects` rather than a single `Effect`. Implement this alongside `ISpellRule` (returning `false` from `TryMatch` so the single-effect path never fires) when the oracle-text shape naturally produces multiple sibling effects that should be represented as a flat array, not a `CompositeEffect`.

Discovery: `SpellAbilityParser` picks this up automatically for any `SpellRuleAttribute`-decorated class that also implements this interface.

[Source](Parsing/Parsers/Spell/IMultiSpellRule.cs)

### `ISpellRule` — *interface*

One spell-effect recognition rule. Each implementation maps a single oracle-text shape to its `Effect` AST node. Rules are discovered by reflection at `SpellAbilityParser` construction via the `SpellRuleAttribute` decoration and dispatched in descending `Priority` order — first match wins.

[Source](Parsing/Parsers/Spell/ISpellRule.cs)

### `SpellRuleAttribute` — *sealed class* : Attribute

Marks an `ISpellRule` implementation for reflection-based discovery by `SpellAbilityParser`. Each decorated rule contributes one oracle-text recognizer to the parser's effect cascade.

<b>Priority convention (range 0–100, default 50, higher = more specific = tried first):</b>

<b>80–100</b> — rules that supersede a more-general sibling (color-disjunction before type-disjunction, IfYouDo variants before plain variants, "this creature" before "a [type]"). Without the bump these would never fire because the more-general rule would shadow them. <b>50</b> — default. Non-overlapping rules whose regex anchors are mutually exclusive. <b>20–40</b> — catch-all / generic rules that should be tried last so a more-specific sibling gets a chance first.

The numeric scheme replaces the old source-order convention: each rule used to declare its priority implicitly by where it appeared in `TryParseEffect`'s cascade. Splitting rules into one-file-per-rule loses that ordering signal, so each rule now states its priority explicitly.

[Source](Parsing/Parsers/Spell/SpellRuleAttribute.cs)

### `SpellRuleHelpers` — *static class*

Shared utilities used across multiple `ISpellRule` implementations. Lives outside the dispatcher so rules can be added without taking a dependency on `SpellAbilityParser` internals.

[Source](Parsing/Parsers/Spell/SpellRuleHelpers.cs)

### `ModifyPTAndGainKeywordSpellRule` — *sealed class* : ISpellRule, IMultiSpellRule

Recognises the composite buff shape: "Target creature gets +N/+M and gains &lt;keyword(s)&gt; until end of turn." This covers any single-target creature buff that combines a P/T modifier with one or more keyword grants, all with until-end-of-turn duration. The keywords group is one or more keyword names joined by " and ". Examples:

"Target creature gets +2/+2 and gains trample until end of turn." "Target creature gets +3/+0 and gains first strike and reach until end of turn." "Target creature gets +1/+1 and gains flying and first strike until end of turn."

Emits a flat list via `TryMatchMulti`: `[ModifyPTEffect, GainAbilityEffect, …]`, one `GainAbilityEffect` per keyword, all sharing a single `UntilEndOfTurnDuration` instance.

The single-effect `TryMatch` always returns false so the flat-list path is the only active route.

[Source](Parsing/Parsers/Spell/Rules/ModifyPTAndGainKeywordSpellRule.cs)

### `ModifyPTAsLongAsSpellRule` — *sealed class* : ISpellRule

## `/Serialization/`

### `PolymorphicTypeAttribute` — *abstract class* : Attribute

Abstract base for attributes that register a derived concrete type into a polymorphic AST hierarchy. Each polymorphic base has its own concrete subclass (e.g., `OracleAbilityAttribute`, `OracleEffectAttribute`) so that the attribute name signals which hierarchy the type belongs to. Discovered at startup by `PolymorphicReflectionConverter{TBase}`.

[Source](Serialization/PolymorphicTypeAttribute.cs)

### `PolymorphicBaseAttribute` — *sealed class* : Attribute

Marks an abstract record/class as the root of a polymorphic AST hierarchy serialized via `PolymorphicReflectionConverter{TBase}`. The named discriminator property is injected by the converter on write and consumed (then stripped) by the converter on read. The discriminator value itself is supplied per-derived-type by a `PolymorphicTypeAttribute` (or one of its subclasses such as `OracleAbilityAttribute`).

[Source](Serialization/PolymorphicBaseAttribute.cs)

### `PolymorphicConverterFactory` — *sealed class* : JsonConverterFactory

A `JsonConverterFactory` that produces a `PolymorphicReflectionConverter{TBase}` for any type marked with `PolymorphicBaseAttribute`. The set of recognised base types is discovered at startup by scanning the MagicAST assembly. Adding a new polymorphic hierarchy means:

Decorate the abstract base with `PolymorphicBaseAttribute`. Author a per-base `PolymorphicTypeAttribute` subclass (e.g., `OracleAbilityAttribute`). Decorate concrete derived types with that attribute.

No edits to this factory, to `MagicASTJsonOptions`, or to any existing base class are required.

[Source](Serialization/PolymorphicConverterFactory.cs)
