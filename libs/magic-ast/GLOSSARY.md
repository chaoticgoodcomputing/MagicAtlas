### `ExploreEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

Explore (Rule 701.44a). "[Permanent] explores. (Reveal the top card of your library. Put that card into your hand if it's a land. Otherwise, put a +1/+1 counter on this creature, then put the card back or put it into your graveyard.)"

MAST records the keyword action's invocation and the exploring subject; the reveal / land-to-hand / +1/+1-counter / graveyard sequence is engine territory per the descriptive-not-engine doctrine (mirroring the SurveilEffect pattern — Surveil similarly records only the keyword and count, not the look/put-into-graveyard machinery).

Filed under `CardFlow` alongside `SurveilEffect`: the keyword's primary descriptive axis is library-reveal followed by put-into- zone, with the +1/+1 counter being a fallback path. The Counter directory hosts effects whose <em>primary</em> shape is counter placement; here that is conditional and secondary.

- **Effect discriminator:** `explore`

[Source](AST/Effects/CardFlow/ExploreEffect.cs)

### `ImpulseEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

"Look at the top N cards of your library. Put one of them into your hand and the rest into [RestDestination]." Models the Impulse/Strategic Planning family: a single atomic action where the controller looks at the top N cards, chooses one to keep in hand, and the remaining cards go to a fixed destination. Rule 701.12 (look).

The two-sentence oracle text is a single game action — "the rest" in the second sentence is a back-reference to the cards revealed by the first. This must not be decomposed into a flat [lookAtCards, …] list; a single ImpulseEffect preserves that semantic coupling.

Variants by RestDestination:

`Graveyard` — Strategic Planning, Rummage `BottomOfLibrary` — Impulse (Visions), Anticipate

- **Effect discriminator:** `impulse`

[Source](AST/Effects/CardFlow/ImpulseEffect.cs)

## `/AST/Effects/Counter/`

### `ProliferateEffect` — *sealed record* : Effect

### `ConditionalPayEffect` — *sealed record* : Effect, IOptionalEffect, IDurativeEffect, IPreventableEffect

"you may pay [cost]. If you do, [effect]" — the conditional-pay triggered pattern. The controller may pay the stated cost; the `IfYouDo` branch carries the consequent effect when payment is made.

Rule 117.3: A player may pay a cost at the time the game asks them to. Rule 603.1: Triggered abilities trigger when their trigger event occurs. The oracle sentence "you may pay [cost]. If you do, [effect]" describes a triggered-ability resolution step in which paying the cost is optional and gated: the consequent fires only if the cost was paid.

This effect is distinct from `UntapEffect { IsOptional = true }` (the Mana Vault shape) in that the payment cost is a first-class field here rather than relegated to the ability's Instructions list. If you do, you gain 1 life.") have the payment as the descriptive axis — the cost is what the oracle text names, not a gate to an effect that already has its own type. The descriptive-not-engine doctrine (MAST records what oracle text says) requires the cost to appear in the AST.

The `IsOptional` flag is always `true` for this effect: "you may pay" is the canonical form; there is no forced-pay variant at the triggered-ability level modelled by this type.

## `/Parsing/Parsers/Spell/`

### `IMultiSpellRule` — *interface*

Extension of `ISpellRule` for shapes that expand to a flat list of effects on `Effects` rather than a single `Effect`. Implement this alongside `ISpellRule` (returning `false` from `TryMatch` so the single-effect path never fires) when the oracle-text shape naturally produces multiple sibling effects that should be represented as a flat array, not a `CompositeEffect`.

Discovery: `SpellAbilityParser` picks this up automatically for any `SpellRuleAttribute`-decorated class that also implements this interface.

[Source](Parsing/Parsers/Spell/IMultiSpellRule.cs)

### `ISpellRule` — *interface*

One spell-effect recognition rule. Each implementation maps a single oracle-text shape to its `Effect` AST node. Rules are discovered by reflection at `SpellAbilityParser` construction via the `SpellRuleAttribute` decoration and dispatched in descending `Priority` order — first match wins.

[Source](Parsing/Parsers/Spell/ISpellRule.cs)

### `SpellRuleAttribute` — *sealed class* : Attribute

Marks an `ISpellRule` implementation for reflection-based discovery by `SpellAbilityParser`. Each decorated rule contributes one oracle-text recognizer to the parser's effect cascade.

<b>Priority convention (range 0–100, default 50, higher = more specific = tried first):</b>

<b>80–100</b> — rules that supersede a more-general sibling (color-disjunction before type-disjunction, IfYouDo variants before plain variants, "this creature" before "a [type]"). Without the bump these would never fire because the more-general rule would shadow them. <b>50</b> — default. Non-overlapping rules whose regex anchors are mutually exclusive. <b>20–40</b> — catch-all / generic rules that should be tried last so a more-specific sibling gets a chance first.

The numeric scheme replaces the old source-order convention: each rule used to declare its priority implicitly by where it appeared in `TryParseEffect`'s cascade. Splitting rules into one-file-per-rule loses that ordering signal, so each rule now states its priority explicitly.

[Source](Parsing/Parsers/Spell/SpellRuleAttribute.cs)

### `TransferCountersOnDeathTriggeredRule` — *sealed class* : ITriggeredRule

"put its counters on target creature you control" — counter-transfer shape that moves all counters from the dying creature to a target controlled creature. The phrase "its counters" is an anaphoric reference to the triggering creature's current counter set (all types and amounts); MAST describes this as `CounterType = "all"` (the sentinel for "every counter type present on the source") with a `DerivedQuantity` source of "its", meaning the count is whatever is on the dying permanent rather than a fixed number (Rule 122.1 — counters are game objects; their quantity is a game state). Oracle text shape (after trigger/effect split): "put its counters on target creature you control" Example: "When Goobling dies, put its counters on target creature you control." (ONE) Priority 60: more specific than the generic `PutCountersTriggeredRule` (priority 50) which requires an explicit counter type ("a +1/+1 counter", "a charge counter", etc.) and would fall through on "its counters" anyway. The higher priority ensures this rule is tried first for the "its counters" surface without ambiguity.

[Source](Parsing/Parsers/Triggered/Rules/TransferCountersOnDeathTriggeredRule.cs)

## `/Serialization/`

### `PolymorphicTypeAttribute` — *abstract class* : Attribute

Abstract base for attributes that register a derived concrete type into a polymorphic AST hierarchy. Each polymorphic base has its own concrete subclass (e.g., `OracleAbilityAttribute`, `OracleEffectAttribute`) so that the attribute name signals which hierarchy the type belongs to. Discovered at startup by `PolymorphicReflectionConverter{TBase}`.

[Source](Serialization/PolymorphicTypeAttribute.cs)

### `PolymorphicBaseAttribute` — *sealed class* : Attribute

Marks an abstract record/class as the root of a polymorphic AST hierarchy serialized via `PolymorphicReflectionConverter{TBase}`. The named discriminator property is injected by the converter on write and consumed (then stripped) by the converter on read. The discriminator value itself is supplied per-derived-type by a `PolymorphicTypeAttribute` (or one of its subclasses such as `OracleAbilityAttribute`).

[Source](Serialization/PolymorphicBaseAttribute.cs)

### `PolymorphicConverterFactory` — *sealed class* : JsonConverterFactory

A `JsonConverterFactory` that produces a `PolymorphicReflectionConverter{TBase}` for any type marked with `PolymorphicBaseAttribute`. The set of recognised base types is discovered at startup by scanning the MagicAST assembly. Adding a new polymorphic hierarchy means:

Decorate the abstract base with `PolymorphicBaseAttribute`. Author a per-base `PolymorphicTypeAttribute` subclass (e.g., `OracleAbilityAttribute`). Decorate concrete derived types with that attribute.

No edits to this factory, to `MagicASTJsonOptions`, or to any existing base class are required.

[Source](Serialization/PolymorphicConverterFactory.cs)
